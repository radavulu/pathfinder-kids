# Architecture: PathfinderKids

_Date: 2026-06-08 · updated after portability/Docker work_

## Summary
A local web app the kids use on a shared computer. A small Python backend serves both the
UI and a JSON API, talks to LM Studio for content, validates answers, and stores everything
in SQLite. Related: [[home-kumon-app]], [[deterministic-math-and-proxy-bypass]],
[[portability-and-deployment]], [[difficulty-and-intensity]], [[modular-backend]].

## Decision
- **Backend:** Python **FastAPI**, served by uvicorn; serves static frontend + REST API.
  Health: `GET /api/health`.
- **Database:** **SQLite**, single file (`homekumon.db`). Tables: children, child_levels,
  time_targets, problems, answers, badges, settings, sessions.
- **Frontend:** **vanilla HTML/CSS/JS** (no framework), themed per child via CSS variables.
- **Content engine:** **LM Studio** (OpenAI-compatible API at `http://localhost:1234/v1`),
  model auto-detected; reading/logic generated by the model, **math computed deterministically**.
- **Data location:** **`./data/homekumon.db`** next to the app (where `run.sh` lives). Override via
  `HOMEKUMON_DATA_DIR` (e.g. OneDrive for cloud backup). Portable via `scripts/export-data.sh` / `import-data.sh`.
- **Run paths:**
  - **Native:** `run.sh` (macOS/Linux) + `run.bat` (Windows) — see [[portable-launchers]].
  - **Docker:** `docker-run.sh` → `docker compose`; image `homekumon:latest`; LM Studio on
    host via `host.docker.internal:1234`; data bind-mount to `/data`.
- **Leveling:** auto up at ≥80%; manual adjust via [[difficulty-and-intensity]].

## Rationale
- The user is a cloud engineer on macOS; a small FastAPI + SQLite app is robust, transparent,
  and easy to extend. SQLite needs no server. Vanilla JS avoids build tooling for a home app.
- LM Studio runs locally and is already set up by the user; OpenAI-compatible API keeps the
  client simple.
- OneDrive-default data dir gives free cloud backup of the kids' progress (user opted in).
- **2026-06-08 update:** default is now **`./data`** beside the app; OneDrive only when `HOMEKUMON_DATA_DIR` is set.
- Docker optional for machines where Python setup is annoying; native `run.sh` remains primary
  for daily use on the family Mac.

## Alternatives considered
- **Single self-contained HTML file (localStorage):** rejected — fragile (CORS, no real
  persistence, no server-side validation).
- **Node/React app:** rejected — heavier tooling than a home app needs.
- **Model judges all answers (incl. math):** rejected for math — slower and unreliable on
  arithmetic; see [[deterministic-math-and-proxy-bypass]].
- **PIN-locked parent dashboard:** the user chose **open, no PIN** for simplicity.
- **Nightly scheduled generation (cron):** the user chose a **manual "Prepare" button**.
- **Pre-built Docker registry image:** deferred — local `docker compose build` for now.

## Key files
`app/config.py` (DATA_DIR/OneDrive detection), `app/db.py` (schema/seed),
`app/main.py` (app factory + static mount), `app/routes/` (HTTP routers: kid, parent, pages),
`app/services/` (children, generation, grading), `app/schemas.py` (API models),
`app/lmstudio.py` (model client), `app/content.py` (generation lifecycle),
`app/starter_bank.py` (offline fallback problems), `app/leveling.py`, `app/validation.py`,
`app/rewards.py`, `app/curriculum.py` (ladders), `web/` (UI), `scripts/` (find_port, export, import),
`Dockerfile`, `docker-compose.yml`, `docker-run.sh`.
